{% comment %} The sidebar's navigation, rendered from apps/core/navigation.py. Two tiers, because there are 35 rows across 8 sections and a single scrolling column of that is a list nobody reads — by the time Finance is open it is 11 rows deep and Settings is below the fold. rail one glyph per module, always visible, 8 of them panel the rows of one module at a time So the most a reader ever faces is 11 rows instead of 35, and which module they are in is legible without reading a word. Every panel is rendered server-side and all but one carries `hidden`. Switching is then a class change rather than a fetch, the search can look through rows that are not on screen, and the whole thing still works with no JavaScript at all: each rail glyph is a real link to the first row of its module, so clicking one navigates instead of switching. The peek is an enhancement, not the mechanism. This template knows about sections, rows and active state, and nothing about any particular module — adding a screen is an entry in that file, not markup here. {% endcomment %}
